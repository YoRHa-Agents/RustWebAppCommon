# Rust Web Common 研究章程
> 更新时间: 2026-04-01

## 目标
本章程将原始 brief 收敛为一套可执行的研究问题、评价维度和边界约束，用于指导后续案例采样、对比矩阵构建与方案建议输出。当前轮次只产出研究资产，不做代码实现、不做远程 clone、不做外部网页 demo 搭建，也不读取 `/home/agent/workspace/Enva`。

## 关键决策问题
1. `RustWebAppCommon` 的 `common` 层应该抽象到哪一层，哪些能力必须沉淀在公共层，哪些能力必须留在各业务仓库中。
2. 统一底座如何同时覆盖跨平台构建、更新、release、部署、GitHub Pages 和在线 demo，而不把业务仓库锁死在单一路线。
3. 统一命令行入口应如何组织，才能在给定 `host` 与 `port` 的前提下同时支持页面启动、子页面跳转和后续扩展。
4. 面向 agent 的 `README + index + 子主题入口` 信息架构应该如何设计，才能降低主 agent 上下文占用并利于 subagent 并行接入。
5. 风格化 markdown 应在哪一层定义，如何在不绑定具体业务内容的前提下沉淀 Nier: Automata 黑白灰主题方向的排版与语义约束。
6. 在未来扩展到设计文档、实现任务和 demo storyboard 时，哪些研究结论必须先锁定，哪些可以并行推进。

## 当前研究范围
### 纳入范围
- 跨平台构建与打包能力的候选模式。
- 更新、release 与部署流程的候选模式。
- GitHub Pages 与在线 demo 的候选承载模式。
- 统一 CLI 启动入口、`host` / `port` 参数与页面路由关联。
- 面向 agent 的结构化 `README`、`index` 与低上下文入口设计。
- 风格化 markdown 与主题系统的约束层级。
- 公共层与业务仓库之间的职责边界。

### 暂不纳入范围
- 当前轮直接实现 Rust 工程骨架或 Web UI。
- 当前轮创建可运行 demo、部署脚本或 CI/CD 流程。
- 当前轮外部仓库 clone、外网 best practice 全量检索或性能基准对比。
- 当前轮读取 `/home/agent/workspace/Enva` 并把其约束并入结论。
- 当前轮输出最终技术选型结论或唯一标准答案。

## 评价维度
| 维度 | 关注问题 | 好信号 | 坏信号 |
|---|---|---|---|
| 技术栈契合度 | 是否与 Rust + Web 双形态长期兼容 | 既支持本地运行也支持 Web/demo 交付 | 只能覆盖单一运行形态 |
| 跨仓复用性 | 多个仓库是否能稳定依赖同一底座 | 公共层职责清晰、接口边界稳定 | 公共层侵入业务实现细节 |
| 运维复杂度 | 构建、更新、发布、部署是否可控 | 路径清晰、故障面可枚举 | 需要大量手工步骤或隐式状态 |
| Agent 接入成本 | 新 agent 是否能低上下文接入 | 入口统一、索引明确、样本可复用 | 文档碎片化、入口混乱 |
| 风格一致性 | 主题与信息层次是否可统一传播 | 结构规范可独立复用 | 风格依赖人工解释或临时约定 |
| 演示成本 | demo 是否容易搭建与维护 | 能快速产出可展示 storyboard 或静态演示 | 需要高维护成本才能展示核心价值 |
| 迁移成本 | 从现有仓库迁移到 common 的阻力有多大 | 可渐进接入、可分阶段落地 | 一次性重构要求过高 |

## 本地基线信号
- `openai-agents-python` 提供了 `README + 分主题 README + 示例运行器` 的三段式入口模式，可作为 agent 友好导航样本。
- `agentic-context-engine` 提供了 `examples/README + quick start + integrations` 的层级化文档入口，可作为低上下文导航与渐进深入样本。
- `ContextOS` 提供了 `README + wiki/architecture + CLI/MCP 统一叙事` 的架构表达方式，可作为公共层能力叙事与分层说明样本。
